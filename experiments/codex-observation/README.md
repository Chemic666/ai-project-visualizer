## Read probe boundaries

RPC allowlist: `initialize`, `thread/list`, `thread/read`, `thread/loaded/list`; only `initialized` is emitted as a client notification. No start/resume/fork/turn/config/auth/approval RPCs. Unexpected server requests are not answered. The script terminates only its own disposable app-server process.

The planned history probe filters exact cwd, uses `useStateDbOnly:true`, checks at most ten listed records and reads at most two per project. It does not fully paginate, wait for live events, or validate a formal plan. A successful future run would still need explicit comparison with the externally started Session and the remaining Spike matrix.

The server may initialize local runtime storage or logging on startup; “read-only RPC” does not promise a process with zero filesystem writes. No persistent configuration overrides are made.

Raw protocol responses and stderr remain in memory. Evidence uses fixed classifications, item counts and transient aliases. It never persists private titles, prompts, raw IDs, code, tool output or tokens. Generated schema and the contract summary are **not observed event fixtures**. There are no positive session-event fixtures in this run.
