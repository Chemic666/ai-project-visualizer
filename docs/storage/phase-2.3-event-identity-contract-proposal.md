## 2. Recommended unified contract

1. **Conditional source ID, mandatory internal ID.** Every NormalizedEvent retains its independently allocated internal EventId. Source identity may be absent. `sourceEventId` is mandatory **only inside `sourceIdentity.kind = source_event`**, when the source provides a stable event identity or an Adapter has independently demonstrated an event-specific identity capability. No new Adapter identity generation algorithm is approved here. Batch cursor/title/time/payload similarity cannot substitute for that proof.
2. **No-identity degradation.** Keep the current Core behavior: original internal IDs deduplicate APV's journal replay; a new normalization ID without stable source_event identity can create another accepted event/effect. Declare at-least-once/repeated-observation limitations. Core does not guarantee delivery, external retry dedup or exactly-once. Do not silently reject all identity-less sources or invent an ID to claim otherwise.
3. **Durable scope — existing Storage proposal, not a new Core key.** Design §4 supplies one project-scoped CoreState per Project/store generation. Within that validated boundary, preserve internal EventId uniqueness and a conditional SourceId/sourceEventId key; conceptual durable scope is **Project/store binding + generation + SourceId + sourceEventId**. Project/generation can be implicit in the admitted DB, not new mandatory envelope fields. SourceId must cover the source's actual uniqueness namespace, including session/stream scope when IDs are only local there; Storage cannot bolt a stream field onto a Core key that ignores it. SourceId remains an internal neutral identity, not an external thread ID. Do not reuse a retired generation or restore several unrelated Project ledgers into one store state.
4. **Ledger is not a source ID.** Persist the canonical allowlisted event with its original internal EventId/body, provenance references and committed sequence/ordinal. Source-provided identity is an optional external claim, never equal by definition to EventId. ledgerSequence identifies a local Project-generation commit; snapshotWatermark identifies the exact cache cut. A checkpoint-only commit or fencing-only control operation does not fabricate a Core input event.
5. **Claims before key replay.** At the future Storage boundary, validate identity scope and compare existing claims before invoking Core's replay shortcuts. Same internal ID requires the same complete persisted event; a new internal ID with the same stable source key may differ only in internal ID/receivedAt under design §7.2. Changed project/session/type/payload/source metadata/causal references conflict rather than overwrite. Canonical claim encoding/comparison still needs implementation and independent tests; no digest algorithm or new Core rejection API is introduced here. A duplicate reuses the original canonical event/Assertions, not a rewritten claim or extra accepted alias.
6. **Cursor represents consumption, including multiple events.** Preserve the existing Core cursor reference branch as input metadata. It neither authorizes resume/ACK nor stores a consumption checkpoint. Proposed Storage checkpoints use SourceId + neutral stream + generation + codec, opaque prior/new positions, and explicit canonical input/unit coverage. Several different event IDs may share one cursor and must all remain eligible; do not put event-unique constraints on cursor/revision. An Adapter must separately verify complete-unit/ordering semantics; opaque strings are not sortable. Missing reliable resume capability leaves the checkpoint absent/unchanged.
7. **Cursor advancement is conditional and atomic.** Advance only after all accepted inputs needed for the declared unit are durably covered, expected prior position matches, no gap/conflict/rejection remains, and the whole guarded Project transaction commits. Event/Assertions/history/dedup and any generated Snapshot/body/watermark/vector remain consistent. Partial batch progress requires an independently verified item-offset capability; otherwise retain the last complete unit. If matching duplicates finish a newly verified unit, design §7.2 permits a checkpoint-only receipt/cut with unchanged Core state and no alias event; this path is still unimplemented/untested. No storage quota error permits dropping input and advancing Cursor.
8. **COMMIT and ACK are separate.** No confirmed publication or source-consumption ACK before successful COMMIT. After COMMIT-before-ACK failure, recover a healthy complete cut and reconcile original operation/intent and canonical input coverage under valid ownership. A matching receipt/source claim prevents another canonical effect for that stable identity; current head, not the historical receipt state, is publishable. A new checkpoint requires its own guarded atomic commit; an already committed covered unit may be re-ACKed. For identity-less external redelivery with a new EventId, that dedup guarantee does not apply. Unknown COMMIT requires settlement before fresh-connection absence checks; missing ACK alone proves nothing. Actual source ACK/resume capabilities remain independently pending.

This separates four concepts already proposed in design §7: stable source key, sourceCursor, local ledgerSequence and snapshotWatermark. The optional envelope metadata and durable consumption checkpoint remain different contracts; no parallel framework or new persistence identity scheme is required.

## 4. Compatibility, references and acceptance effects

**Phase 1 compatibility: retained.** No type/field rename, new required identity, generation member, runtime comparator, AssertionId derivation or EventApplicationResult change. Optional/cursor inputs remain legal; existing same-ID/source-pair replay and alias behavior remain unchanged. Imported histories are not retroactively merged, re-IDed, deduplicated by cursor or reclassified under a newly invented source namespace.

Original canonical EventId, AssertionId, source/event/revision/time references, provenance and Correction history must survive storage and restore. Source retries cannot rewrite the original receivedAt or promote agent_reported to observed/verified. Existing repeated identity-less observations retain their distinct events/assertions. Trusted Correction lifecycle images remain versioned history; this clarification does not implement or expire corrections. A conflicting or unsupported import is unavailable/rejected, not repaired by deleting references or creating synthetic evidence.

Design §4's project-scoped store admission provides the outer durable generation boundary without changing CoreState; it must be implemented/validated, not assumed from its TypeScript shape. Generation is not an extra dedup predicate in current Core. Missing source namespace proof, unsupported cursor codec, conflicting claim or foreign Project/generation must block affected persistence/checkpoint/ACK rather than rewrite history. Privacy projection cannot mask a source key into a collision and still claim equivalent identity; admission must honor P01/P02 and approved allowlists.
